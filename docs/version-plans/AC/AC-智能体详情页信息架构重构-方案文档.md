# AC 智能体详情页信息架构重构方案

> 状态：待确认
>
> 本文先确认页面已有功能、用户任务与信息层级，不进入代码实现。

## 一、需求

### 1. 背景

当前智能体详情页同时承载智能体状态、假人控制、主智能体对话日志、QQ 对话日志、主配置、QQ 配置、上下文统计、用量和待办事项。

现有结构存在以下问题：

1. “信息”页实际展示对话日志，名称与内容不一致。
2. 页面存在“信息 / 配置 / QQ → 对话 / 配置 → 六个配置分区”的多级导航，用户难以判断功能位置。
3. 主对话和 QQ 对话被拆成两个页面，但本质都是运行日志，只是来源不同。
4. 主配置和 QQ 配置存在重复项，尤其是定时触发、工具、技能和人设。
5. 状态、开关、上线按钮、页签、删除按钮挤在同一行，主次关系不清楚。
6. 删除、清空历史等操作缺少统一的危险操作规范。
7. 多数操作失败只写入控制台或被静默处理，用户无法确认操作是否成功。
8. 右侧监控栏长期占用空间，但上下文、用量和待办与当前运行日志缺少直接关联。

### 2. 重构目标

本次重构目标不是增加更多功能，而是重新组织已有能力：

- 页面默认服务于“运行监控”。
- 用户进入智能体后第一眼看到实时日志和关键运行状态。
- 主智能体、游戏、QQ群、QQ 私聊统一按“对话渠道”理解。
- 页面导航最多两层，视觉上优先保持一层。
- 配置集中在一个页面内，通过分段而不是多级页签组织。
- 所有按钮使用统一尺寸、圆角、颜色和状态反馈。
- 重要操作必须有明确的加载、成功、失败和确认反馈。
- 保留现有后端能力边界，不假设新增会话 API、渠道 API 或日志 API。

### 3. 用户核心任务

按优先级排列：

#### P0：运行监控

1. 判断智能体是否启用、假人是否在线、QQ 是否连接。
2. 控制假人上线或下线。
3. 查看智能体当前及最近的对话、思考和工具调用。
4. 区分日志来自游戏还是 QQ。
5. 查看上下文占用和响应状态。
6. 在异常时获得明确的错误反馈。

#### P1：配置维护

1. 修改名称、头像、模型和人设。
2. 管理技能和现有工具配置摘要。
3. 配置 QQ 账号、群组和仅 @ 触发。
4. 配置 QQ 独立模型、人设、工具和技能。
5. 配置自动触发计划。
6. 保存或放弃修改，并知道当前是否存在未保存内容。

#### P2：低频管理

1. 查看系统提示词编译结果。
2. 清空 QQ 对话历史并开始新对话。
3. 删除智能体。

### 4. 现有功能确认

#### 4.1 身份与运行控制

- 智能体头像或名称首字占位。
- 智能体名称。
- 智能体启用/禁用。
- 智能体运行状态与最后活跃时间。
- QQ 在线、连接中、离线状态。
- 假人在线、离线状态。
- 假人上线、下线。
- 删除智能体及二次确认。

#### 4.2 主运行日志

- 加载历史消息。
- 每次增加 50 条历史。
- 每 5 秒检查新消息。
- 接收实时流式事件。
- 展示用户、系统、智能体和工具结果。
- 展示思考过程。
- 展示工具参数、结果、错误和耗时。
- 手动刷新。
- 显示“LLM 响应中”。

#### 4.3 QQ 运行日志

- 加载 QQ 专属历史。
- 每次增加 30 条历史。
- 每 5 秒检查新消息。
- 接收实时流式事件。
- 手动刷新。
- 清空 QQ 历史并开始新对话。

当前限制：流式事件只有智能体 ID，没有渠道标识，因此不能可靠地把实时流拆分到具体 QQ 群或私聊。新界面可以按已有历史来源筛选，但不能承诺后端尚未提供的细粒度实时渠道分流。

#### 4.4 主智能体配置

- 名称和头像。
- 主模型。
- QQ 模型，可跟随主模型或独立选择。
- 压缩模型，可跟随主模型或独立选择。
- 身份描述和个性特征。
- 工具数量摘要。
- 技能启用/禁用。
- 定时触发。
- 系统提示词只读预览。

#### 4.5 QQ 配置

- 启用 QQ。
- 选择 QQ 账号。
- 选择绑定群组。
- 仅 @ 触发。
- 定时触发，支持关闭、Cron、固定间隔和随机时段。
- QQ 工具跟随主智能体或独立配置。
- QQ 技能跟随主智能体或独立配置。
- QQ 人设与系统提示词。

#### 4.6 运行辅助信息

- 上下文占用比例和 Token 分项。
- 今日、本月及最近 7 日用量。
- 待办事项摘要。

### 5. 本次不做

- 不新增桌面端主动聊天能力。
- 不新增后端日志类型。
- 不新增 QQ 群或私聊会话 API。
- 不新增工具编辑能力；现阶段主配置仍只显示已有工具摘要。
- 不重新设计创建向导。
- 不改造全局左侧主导航。
- 不引入第三层导航。

### 6. 验收标准

1. 顶层只保留“运行”和“设置”两个入口。
2. 默认进入“运行”。
3. “运行”页不再嵌套额外页签。
4. 对话渠道栏可收起，但收起只是空间切换，不形成新导航层。
5. “设置”采用一个滚动页面，最多四个一级分段，不再使用左侧六项配置导航。
6. QQ 对话和主对话不再作为两个顶层页面。
7. QQ 定时配置只有一个入口。
8. 删除智能体只出现在设置页底部。
9. 清空历史必须明确说明影响范围并二次确认。
10. 保存、上线、启用、删除、清空历史均提供进行中、成功和失败反馈。
11. 窄宽度下先收起渠道栏和辅助监控，不压缩日志正文到不可读。

## 二、架构

### 1. 信息架构原则

- **只保留两种工作模式**：运行、设置。
- **渠道是筛选，不是页面**：游戏和 QQ 是日志来源，不再各自占用独立页签。
- **设置是单页，不是设置中心套设置中心**：使用纵向分段和页内定位。
- **状态与操作分离**：状态标签只读，按钮只承担操作。
- **高级和危险操作下沉**：低频操作不占据顶部主操作区。

### 2. 页面总体结构

```text
智能体详情
├─ 紧凑身份栏
│  ├─ 头像、名称、启用状态、最后活跃
│  ├─ QQ 状态、假人状态
│  └─ 假人上线/下线
├─ 顶层导航
│  ├─ 运行（默认）
│  └─ 设置
└─ 当前页面内容
```

整个详情页只存在一个顶层导航，不再保留“信息 / 配置 / QQ”和 QQ 内部的“对话 / 配置”嵌套结构。

### 3. 紧凑身份栏

#### 左侧：身份

- 36×36 头像。
- 智能体名称。
- “已启用 / 已禁用”状态标签。
- 最后活跃时间。

#### 右侧：状态与主操作

- QQ 状态标签。
- 假人状态标签。
- “上线 / 下线”主按钮。

#### 交互约束

- 启用/禁用不再使用无文字的小开关紧贴名称，改为可理解的状态按钮或带明确标签的开关。
- QQ、假人状态使用标签样式，不表现为可点击按钮。
- 顶部不显示删除按钮。
- 顶部不显示刷新按钮；刷新属于运行日志工具栏。

### 4. 运行页

运行页采用“可折叠渠道栏 + 日志主体 + 可折叠运行摘要”的平面结构。

```text
运行页
├─ 渠道栏（可收起）
├─ 日志主体
└─ 运行摘要（复用现有右侧信息，可收起）
```

#### 4.1 渠道栏

展开时宽度约 200–220px，展示：

- 全部日志。
- 游戏日志。
- QQ 日志。
- QQ 历史清空操作，仅在 QQ 渠道选中时出现。

收起时宽度约 44–48px，只保留：

- 展开按钮。
- 全部、游戏、QQ 三个来源图标。
- 当前选中状态。

说明：当前后端无法可靠拆分到每个 QQ 群或私聊，因此第一阶段不展示虚假的“QQ群会话列表”。等后端提供会话 ID 和渠道元数据后再扩展，避免界面承诺超过实际能力。

#### 4.2 日志工具栏

只保留以下操作：

- 当前来源名称。
- 消息类型筛选：全部、消息、工具、系统。
- 自动跟随开关。
- 刷新。

筛选使用同一排轻量控件，不再增加页签。

#### 4.3 日志主体

继续复用现有消息能力：

- 普通消息。
- 思考过程折叠块。
- 工具调用折叠块。
- 流式响应。
- 加载更多。

体验优化：

- 时间、来源、角色采用固定信息顺序。
- 工具成功、失败使用统一状态色。
- 自动跟随开启时保持在最新事件；用户主动向上滚动后自动暂停。
- 加载历史放在列表顶部，避免底部“加载更多”与实时流方向冲突。
- 加载失败显示可重试错误态，不再伪装成“暂无消息”。

#### 4.4 运行摘要

复用现有右侧栏能力，但不再作为永久独立页面栏。默认在宽屏显示，窄屏收起：

- 上下文窗口。
- Token 用量。
- 待办事项。

运行摘要只允许展开或收起，不再包含二级导航。

### 5. 设置页

设置页是一个纵向滚动页面，只分四段。顶部提供固定的“放弃修改 / 保存更改”，不增加设置子页签。

```text
设置
├─ 基本与模型
├─ 人设与能力
├─ 连接与自动化
└─ 危险操作
```

#### 5.1 基本与模型

- 名称。
- 头像。
- 主模型。
- 压缩模型。
- 添加模型入口。

QQ 模型不再混在主模型卡片中，移动到“连接与自动化”的 QQ 区块。

#### 5.2 人设与能力

- 身份描述。
- 个性特征。
- 主智能体工具摘要。
- 主智能体技能配置。
- 主系统提示词只读预览。

系统提示词是编译结果，不与人设源字段混为同一种编辑方式。

#### 5.3 连接与自动化

使用两个普通内容块，不使用新页签。

**QQ 连接**

- 启用 QQ。
- QQ 账号。
- 绑定群组。
- 仅 @ 触发。
- QQ 模型：跟随主模型或独立模型。
- QQ 人设：跟随主智能体或独立配置。
- QQ 工具：跟随主智能体或独立配置。
- QQ 技能：跟随主智能体或独立配置。

独立配置关闭时只展示继承摘要，不展开完整表格；开启后在当前位置展开内容。

**自动触发**

- 关闭。
- Cron。
- 固定间隔。
- 随机时段。
- 时区。
- 触发提示词。

定时触发只保留这一处入口，删除主配置中的重复入口。

#### 5.4 危险操作

- 删除智能体。
- 红色描边按钮。
- 与普通保存区至少间隔一个完整区块。
- 保留名称确认和不可恢复说明。

清空 QQ 历史不放在这里，因为它只影响运行页中的 QQ 日志，应放在 QQ 渠道上下文中。

### 6. 层级限制

为了避免排版复杂，强制遵循以下限制：

1. 页面最多一个顶层页签栏。
2. 内容区不再出现第二排页签。
3. 设置页最多四个一级标题。
4. 一个分段内最多一层可展开内容。
5. 不同时使用“页签 + 左侧导航 + 手风琴”。
6. 状态标签、筛选项、操作按钮必须有不同视觉语义。
7. 标题字号最多三级：页面标题、分段标题、字段标题。

### 7. 按钮与视觉规范

#### 7.1 按钮层级

| 层级 | 用途 | 示例 |
|---|---|---|
| 主要按钮 | 当前页面唯一主任务 | 上线、保存更改 |
| 次要按钮 | 可恢复的辅助操作 | 放弃修改、刷新 |
| 图标按钮 | 明确且高频的局部操作 | 收起渠道栏 |
| 危险按钮 | 不可恢复操作 | 删除智能体、清空历史 |

#### 7.2 统一规则

- 常规按钮高度统一为 32px。
- 紧凑图标按钮为 28–32px 正方形。
- 圆角统一为 8px。
- 同一工具栏内按钮间距统一为 8px。
- 主要按钮使用实色；次要按钮使用白底描边；危险按钮使用红色描边。
- 不使用绿色、橙色大面积按钮表达普通状态。
- 状态通过小圆点和浅色标签表达。
- 所有图标按钮提供 Tooltip 和可访问名称。

### 8. 状态与反馈

每个异步操作统一具备四态：

1. 默认。
2. 进行中：禁用并显示加载状态。
3. 成功：更新真实数据并给出轻量成功提示。
4. 失败：保留原状态并显示可见错误提示。

具体要求：

- 切换智能体时必须清理旧 `currentAgent`，并显示详情加载状态。
- Store 不再吞掉更新和删除错误，错误应返回调用组件。
- 上线、下线和启用操作失败时回滚乐观状态。
- 删除失败时保持弹窗和当前页面，不得返回导航页。
- 清空 QQ 历史只有后端成功后才清空前端列表。
- 设置页存在未保存修改时，切换到“运行”或其他智能体前提示用户。
- QQ 系统提示词弹窗内按钮命名为“应用到表单”，页面顶部“保存更改”才代表持久化。

### 9. 组件边界

建议组件划分如下：

```text
AgentInstanceView
├─ AgentHeader
├─ AgentViewTabs
├─ AgentRuntimeView
│  ├─ ChannelRail
│  ├─ RuntimeToolbar
│  ├─ UnifiedLogPanel
│  │  ├─ MessageList
│  │  ├─ ThinkingBlock
│  │  └─ ToolCallBlock
│  └─ RuntimeSummary
└─ AgentSettingsView
   ├─ BasicModelSection
   ├─ PersonaCapabilitySection
   ├─ ConnectionAutomationSection
   └─ DangerZone
```

原则：

- `AgentInstanceView` 只负责装配和当前智能体生命周期。
- 运行日志加载逻辑抽成统一 Hook，通过 `source = all | game | qq` 决定历史 API 和筛选。
- `MessageList`、`MessageBubble`、`ThinkingBlock`、`ToolCallBlock` 继续复用。
- 主技能和 QQ 技能复用同一个列表组件。
- 定时配置只保留一个组件，并补齐随机时段模式。
- QQ 绑定继续复用现有 `QQBindSection`。

## 三、执行

### 阶段 1：修复数据与错误基础

1. 修复切换智能体时旧 `currentAgent` 残留问题。
2. 统一 Summary、Config 和运行状态的展示来源。
3. 让 Store 的更新、删除错误能够向 UI 抛出。
4. 补齐配置表单初始化字段，确保技能、定时等已保存值正确回显。
5. 修复工具启用数量统计。

验收：切换、保存、删除失败时不再出现错误页面跳转或旧数据闪现。

### 阶段 2：重构页面骨架

1. 将顶层导航改为“运行 / 设置”。
2. 抽出紧凑 `AgentHeader`。
3. 删除标题栏中的删除图标。
4. 将删除确认逻辑移动到设置页危险操作区。
5. 将现有右侧监控栏改造成可折叠 `RuntimeSummary`。

验收：页面只有一排顶层导航，默认进入运行页。

### 阶段 3：统一运行日志

1. 抽取主日志和 QQ 日志的公共加载、轮询、流式订阅逻辑。
2. 增加可折叠 `ChannelRail`，第一阶段只提供全部、游戏、QQ。
3. 增加消息类型筛选、自动跟随和统一刷新。
4. 调整加载更多到列表顶部。
5. 为加载失败、刷新失败、流式失败提供可见状态。
6. 为“清空 QQ 历史”增加明确文案和确认弹窗。

验收：不切换顶层页面即可查看游戏与 QQ 日志；渠道栏收起后日志区域自然扩展。

### 阶段 4：简化设置页

1. 将主配置与 QQ 配置合并为一个设置页面。
2. 按“基本与模型 / 人设与能力 / 连接与自动化 / 危险操作”分组。
3. 移除 QQ 配置六项左侧导航和空的“偏好”入口。
4. 将 QQ 模型迁入 QQ 连接区块。
5. 将定时配置收敛到一个入口，并统一支持模式。
6. 工具、技能和 QQ 独立配置使用继承开关和就地展开。
7. 增加脏数据检测、放弃修改和离开确认。

验收：用户在一个设置页面完成所有现有配置，不经过二级配置导航。

### 阶段 5：统一视觉与交互

1. 统一按钮高度、圆角、间距和层级。
2. 统一状态标签颜色和文案。
3. 为图标按钮增加 Tooltip。
4. 统一空状态、加载状态和错误状态。
5. 验证窄窗口下渠道栏和运行摘要的自动收起。
6. 检查键盘焦点、可访问名称和对比度。

验收：同类操作视觉一致，状态和按钮不会混淆，窗口收窄时日志仍保持可读。

### 阶段 6：验证范围

#### 功能验证

- 切换智能体。
- 启用/禁用。
